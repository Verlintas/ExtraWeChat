# WeChat 4.1.15 (build 270115) 防撤回补丁点

> 仅适用于 **App Store 版微信 4.1.15.35 / `CFBundleVersion` 270115 / arm64**。
> 其他构建号不要复用这些地址；先运行 `tools/locate_revoke.py` 重新定位。

## 1. 识别信息

```text
CFBundleIdentifier       com.tencent.xinWeChat
CFBundleShortVersionString 4.1.15
CFBundleVersion          270115
WeChatBundleVersion      4.1.15.35
Channel                  App Store (Contents/_MASReceipt/receipt)
Arch                     arm64 (universal 二进制)
Dylib                    Contents/Resources/wechat.dylib
Dylib size               335 MB universal
arm64 slice offset       0xad0c000
arm64 slice size         0xa185a60
```

## 2. 补丁点

| 名称 | arm64 VA | slice 内文件偏移 | fat 内绝对偏移 | 原字节 | 补丁字节 |
| --- | ---: | ---: | ---: | --- | --- |
| silent（静默） | `0x4bbb1dc` | `0x4bbb1dc` | `0xf8c71dc` | `40 10 00 34` | `82 00 00 14` |
| keeptip（留提示） | `0x4bbb97c` | `0x4bbb97c` | `0xf8c797c` | `60 E6 00 F9` | `7F E6 00 F9` |

`parseRevokeXML` 入口：`E = 0x4bbaf6c`。

几何关系：

```
silent  = E + 0x270          = 0x4bbaf6c + 0x270 = 0x4bbb1dc
keeptip = E + 0x270 + 0x7a0  = 0x4bbb1dc + 0x7a0 = 0x4bbb97c
newmsgid 字段： [x19, #0x1c8]
签名代：        4.1.13+ (269574+)
```

## 3. 指令含义

```asm
; E + 0x270
40100034   cbz  w0, 0x4bbb3e4      ; 原始：解析结果为空/失败时跳过撤回处理
82000014   b    0x4bbb3e4          ; silent：无条件跳过

; E + 0x270 + 0x7a0
60E600F9   str  x0,  [x19, #0x1c8] ; 原始：写入 newmsgid
7FE600F9   str  xzr, [x19, #0x1c8] ; keeptip：清零 newmsgid
```

- silent：撤回逻辑被跳过，消息保留，不显示撤回提示。
- keeptip：撤回解析继续执行（私聊提示会出现），但「要删除的消息 ID」被清零，下游删不到消息。
  群聊提示可能不出现，这是 `newmsgid` 同时控制「删哪条」和「群提示插在哪条」导致的已知限制。

## 5. 校验方法

### 5.1 只读定位

```bash
python3 tools/locate_revoke.py --app /Applications/WeChat.app
```

应输出：

```
Generation:    4.1.13+ (269574+)
parseRevokeXML entry E: 0x4bbaf6c
silent  VA:    0x4bbb1dc  40100034 -> 82000014  [pristine]
keeptip VA:    0x4bbb97c  60E600F9 -> 7FE600F9  [pristine]
```

### 5.2 检查 fat 内字节

```bash
xxd -s 0xf8c71dc -l 4 /path/to/WeChat.app/Contents/Resources/wechat.dylib
# silent 原始: 4010 0034
# silent 补丁: 8200 0014

xxd -s 0xf8c797c -l 4 /path/to/WeChat.app/Contents/Resources/wechat.dylib
# keeptip 原始: 60e6 00f9
# keeptip 补丁: 7fe6 00f9
```

### 5.3 重签验证

```bash
codesign --verify --deep --strict --verbose=2 /path/to/WeChat.app
echo $?   # 0
```

## 6. 多版本适配

从 v0.1.4 起，定位器优先读取 `tools/revoke_profiles.json` 中的构建配置（42 个
微信 4.x arm64 构建，覆盖到 4.1.15.55 / 270135），未收录的构建再回退到
`parseRevokeXML` 的 arm64 几何签名自动定位。构建号是唯一标识，不能只按
`CFBundleShortVersionString` 复用地址。

当前只支持 Apple Silicon；Intel、微信 3.8.x、4.1.7 不在范围内。
详见 [`COMPATIBILITY.md`](COMPATIBILITY.md)。

## 7. 新版本如何扩展

微信重编译 `parseRevokeXML` 后，可能出现新的「代」（`cbz` 跳转距离、`delta`、字段偏移变化）。
定位器会报 `no signature hit`；此时：

1. 用 `lipo -thin arm64` 抽取新 dylib；
2. 从 `parseRevokeXML` 的入口开始，找到：
   - `E + 0x270` 处的 `cbz w0`；
   - 之后某条 `str <Rt>, [x19, #newmsgid]`；
3. 记录：`cbz` 原字节、等长 `b` 字节、`delta`、`str` 原/补丁字节、字段偏移；
4. 把这组几何加入 `tools/locate_revoke.py` 的 `SIGNATURES`，并在本文档追加一代；
5. 仍然要在写入前校验原始字节，不能只信地址。

## 8. 自动更新（App Store 版不适用）

App Store 版 `wechat.dylib` 里没有 `XAppUpdateManager` 类（本机验证：`locate_update.py` 报告
`没找到 ObjC 类 XAppUpdateManager`）。App Store 版由 App Store 更新，工具无法也不应阻止它。
官网版（direct）才需要按 `XAppUpdateManager` 的
`startUpdater` / `checkForUpdates:` / `startBackgroundUpdatesCheck:` / `enableAutoUpdate:` 等方法
定位并 patch；这属于后续版本的工作。

## 9. 卸载/还原

还原就是把上表的「补丁字节」写回「原字节」，然后重签：

- silent 还原：`82 00 00 14` → `40 10 00 34`
- keeptip 还原：`7F E6 00 F9` → `60 E6 00 F9`

正式工具应支持 `restore`，并在写入前确认当前字节确实是本工具写的补丁；如果发现未知字节，
拒绝覆盖并提示重装微信。
